# Agents Plus 产品蓝图

## 1. 产品定位

Agents Plus 是面向 AI 编程工具的规则配置控制面，负责安全管理、验证、同步、合并和发布个人及团队 Agent 规则。

## 2. 产品愿景

让用户在任意设备、任意项目和任意 Agent 工具中获得一致、可追溯、可验证且不会误覆盖的工作规则。

## 3. 核心对象

| 对象 | 说明 |
| --- | --- |
| Policy | 规范化的 Agent 规则源文件 |
| Scope | 规则作用域，包括个人、工作区、项目和组织 |
| Adapter | 将 Policy 编译为具体 Agent 工具配置的适配器 |
| Revision | 不可变的规则版本及其父版本关系 |
| Device | 已授权并执行同步的设备 |
| Release | 经过验证、审批并可分发的规则版本 |

## 4. 产品边界

### 4.1 当前核心

- 跨设备同步个人 `~/AGENTS.md`。
- 保存云端不可变版本链。
- 提供上传、拉取、恢复和三方合并。
- 覆盖本地文件前创建备份并执行原子写入。

### 4.2 演进方向

- 从单文件扩展到多文件 Agent 配置。
- 从单一用户扩展到个人、项目和团队规则分层。
- 从文本同步扩展到规则验证、编译和发布。
- 从个人工具扩展到团队治理和企业部署。

### 4.3 非目标

- 不做通用网盘或整个用户主目录同步。
- 不执行规则文件中的命令。
- 不在未经确认的情况下自动覆盖本地内容。
- 不把服务端可读正文包装成端到端加密产品。

## 5. 产品能力地图

### 5.1 同步基础设施

- 文件系统级监听和变更防抖。
- 离线队列、失败重试和网络恢复补偿。
- 本地快照、manifest、备份和原子写入。
- 云端版本链、幂等提交和父版本并发控制。
- 本地、基线、远端三方合并。

### 5.2 规则管理

- 多文件和多格式配置。
- 个人、工作区、项目和组织作用域。
- 规则模块、继承、覆盖、禁用和优先级。
- 规则模板、标签、收藏和稳定版本。
- Agent 工具适配器和目标配置编译。

### 5.3 规则质量

- 敏感信息扫描和上传前拦截。
- 重复、冲突、过期引用和无效路径检测。
- 规则结构、长度、清晰度和可执行性检查。
- 版本差异、来源追踪、影响范围和变更摘要。
- AI 辅助审查、冲突解释和合并建议。

### 5.4 开发者入口

- CLI 登录、状态、同步、差异、历史和恢复。
- VS Code、JetBrains 等编辑器插件。
- GitHub/GitLab 导入、导出和 PR 工作流。
- Git hooks、CI 检查和规则发布流水线。
- 项目初始化和规则模板生成。

### 5.5 团队治理

- 组织、团队、项目和成员模型。
- RBAC、SSO、SCIM 和设备生命周期管理。
- 草稿、审核、审批、发布、回滚和紧急撤回。
- 规则签名、可信设备和篡改检测。
- 审计报表、合规导出和变更通知。

### 5.6 安全与部署

- 系统凭据存储、密钥轮换和设备撤销。
- 端到端加密和恢复密钥流程。
- PostgreSQL 备份、恢复演练和版本保留策略。
- Docker、Compose、Helm 和私有化部署。
- 监控、告警、限流、状态页和灾备。

## 6. 目标用户与场景

### 6.1 个人开发者

- 在公司电脑和家用电脑之间同步 Agent 规则。
- 换机后快速恢复完整 AI 编程环境。
- 查看某条规则的历史来源并恢复稳定版本。
- 在本地和云端同时修改时安全合并。

### 6.2 高级用户

- 为不同项目维护独立规则 profile。
- 将一套规则编译到多个 Agent 工具。
- 在 CI 中检查规则安全性和有效性。
- 使用 CLI 管理远程开发机和自动化环境。

### 6.3 团队和企业

- 统一下发编码、安全和协作规则。
- 审批高风险规则变更并保留完整审计。
- 设备撤销后阻止继续拉取和提交。
- 在私有网络中部署并控制数据驻留。

## 7. 目标架构

```text
规则源 Policy
   ↓
作用域合并 Scope Resolver
   ↓
质量检查 Rule Analyzer
   ↓
目标适配器 Adapter Compiler
   ↓
版本与发布 Revision / Release
   ↓
设备同步 Device Sync
   ↓
本地 Agent 配置
```

### 7.1 客户端

- Next.js 静态导出负责界面、状态和用户确认。
- Tauri/Rust 负责文件、凭据、网络、监听和原子写入。
- 本地同步引擎负责快照、队列、状态机和冲突保护。
- CLI 与桌面端共享同步协议和本地状态模型。

### 7.2 服务端

- Auth Service 负责用户、会话、设备和权限。
- Policy Service 负责规则源、作用域和适配器配置。
- Revision Service 负责不可变版本链、幂等和并发控制。
- Release Service 负责验证、审批、签名、发布和回滚。
- Audit Service 负责安全审计和操作追踪。

## 8. 路线图

### Phase 1：可靠同步

- 统一 hash 契约并补齐回归测试。
- 文件监听、离线队列和重试。
- Diff、备份管理和冲突体验优化。
- 上传前敏感信息扫描。
- CLI 基础命令。

### Phase 2：规则平台

- 多文件配置和 profile。
- 个人、工作区、项目作用域。
- 规则模块、继承和覆盖。
- 规则质量检查。
- Git 集成和编辑器插件。

### Phase 3：智能规则工程

- AI 规则审查。
- AI 冲突解释和合并建议。
- 规则模拟器。
- Agent 配置适配器和编译器。
- 变更影响分析。

### Phase 4：团队治理

- 组织、团队、RBAC 和审批流。
- 规则签名、发布、回滚和紧急撤回。
- SSO、SCIM 和企业审计。
- 私有化部署和数据驻留。

### Phase 5：可信规则基础设施

- 端到端加密。
- 设备密钥圈和恢复流程。
- 可验证版本链。
- 多区域部署和灾备。

## 9. 产品原则

- 默认不静默覆盖用户本地修改。
- 所有规则变更都可追踪、可比较、可恢复。
- AI 只提供建议，最终写入由用户或审批流程确认。
- 规则正文、凭据和敏感信息按最小暴露原则处理。
- 个人体验优先保持简单，企业能力通过作用域和权限扩展。
- 先建立同步可靠性，再扩展规则智能和团队治理。

## 10. 关键成功指标

- 首次绑定成功率。
- 同步成功率和平均同步耗时。
- 冲突检测准确率和冲突解决完成率。
- 本地误覆盖次数为零。
- 版本恢复成功率。
- 敏感信息拦截率和误报率。
- 多设备月活和跨设备同步频次。
- 团队规则采用率和审批周转时间。

## 11. 发布门槛

- 客户端和服务端 hash 契约一致。
- 核心同步、并发、幂等、恢复和冲突路径有自动化测试。
- 生产环境强制 HTTPS、CSP、密钥注入和数据库备份。
- Tauri 安装包完成签名并具备升级与回滚方案。
- 日志不包含规则正文、密码、token、私钥和完整本地路径。
- 至少完成两台设备的真实端到端验收。
